## Proje
GitHub repolarını klonlamadan ve hiçbir kodu çalıştırmadan tarayıp zararlı yazılım hilelerini arayan, VirusTotal / scanrepo.dev benzeri bir web sitesi.
Hedef kitle: bir repoyu klonlamadan, kurmadan ya da IDE'de açmadan önce "bu güvenli mi?" diye soran geliştiriciler.
Kişisel proje, ticari değil. **Kod özeldir** (kullanıcı kararı, 10 Ekim 2026): GitHub reposu private kalır, açık kaynak değildir (`LICENSE`: tüm hakları saklıdır, `package.json` `UNLICENSED`). Sitede reponun kendisine, Issues'a ya da kaynak koda link verilmez; "open-source"/"açık kaynak" yazılmaz. **Sitede iletişim bölümü yoktur** (kullanıcı kararı, 10 Ekim): e-posta, iletişim linki ve `security.txt` yok. **İstisna (17 Ekim, kullanıcı isteği):** tarama sayfasında bir "yanlış sonucu bildir" formu vardır — e-posta/kimlik istemez, bildirimler **özeldir** (yalnızca site sahibi `/dorukadm` panelinden okur, herkese açık değildir). Bu, 10 Ekim'deki "yanlış alarm bildirme yolu yok" kararının yerine geçer; yine de bir iletişim bölümü değildir. Hedef: çalışan bir MVP, temiz mimari, açıklanabilir sonuçlar, iyi test kapsamı ve güçlü bir README.

## Değişmez güvenlik kuralları
1. Taranan repodaki hiçbir kod çalıştırılmaz: install, build, script, alt süreç, `eval`, `new Function`, `vm` yok. Yalnızca okuma. `tests/security.test.ts` kendi kodumuzda `child_process`, `vm`, `worker_threads` ve `new Function` kullanımını yasaklar.
2. Arşiv diske açılmaz. Tarball bellekte, akış (stream) halinde ve limitlerle okunur (`src/engine/limits.ts`): repo boyutu, indirilen byte, dosya/girdi sayısı, dosya başına byte, toplam açılmış byte ve süre bütçesi. gzip açma kendi sayacımızdan geçer (gzip bombası). Symlink, hardlink ve özel dosyalar okunmaz. Motor `fs` import etmez.
3. Release dosyaları indirilmez. GitHub API'nin verdiği `digest` (sha256) gösterilir ve VirusTotal'de aranabilir; özet yoksa "kontrol edilemedi" yazar. `VIRUSTOTAL_API_KEY` varsa bu özetler ve repoya commit'lenmiş programların özetleri VirusTotal'e otomatik sorulur (yalnızca SHA-256 gönderilir, hiçbir dosya yüklenmez ya da indirilmez).
4. Taranan repodan gelen her içerik güvenilmezdir (dosya adı, README, kod parçası, açıklama, dal ve release adları): `src/engine/report.ts` hepsini sanitize eder (görünmez/kontrol/yön karakterleri `[U+202E]` olarak görünür hale gelir, URL'ler `hxxps://evil[.]com` biçiminde etkisizleştirilir, uzunluk sınırlanır). Arayüz yalnızca bu raporu kullanır, React kaçışına güvenir; `dangerouslySetInnerHTML` ve `innerHTML` yasaktır. Repo içeriğinden gelen URL'ler asla tıklanabilir yapılmaz. Tıklanabilir olan tek bağlantılar bizim doğrulanmış parçalardan kurduklarımızdır: `github.com/<owner>/<repo>/blob/<sha>/<yol>#L<satır>` (yol segmentleri encode edilir), `virustotal.com/gui/file/<sha256>` (bulunan dosyalar) ve `virustotal.com/gui/search/<sha256>` (bilinmeyen dosyalar; VT'de yoksa 404 yerine "sonuç yok" gösterir, çünkü yalnızca parmak izi sorulur, dosya yüklenmez) — yalnızca 64 hex karakter ve kendi sitemizdeki `/<dil>/scan/<owner>/<repo>` (doğrulanmış ad, segmentler encode edilir; `src/i18n/config.ts` `scanPath`). Bunlara ek olarak gizlilik sayfasındaki Vercel, Neon ve Google gizlilik politikası adresleri link olabilir.
5. Repoda ve testlerde gerçek zararlı yazılım bulunmaz. Yalnızca kuralı tetikleyen ama kendisi zararsız sahte örnekler (fixture) kullanılır: `.invalid` alan adları, sahte tokenlar, yalnızca mesaj yazdıran base64 içerikler, program olmayan dosya başlıkları.
6. Görünmez ve yön karakterleri (U+200B–U+200F, U+202A–U+202E, U+2066–U+2069, U+2028, U+2029, varyasyon seçiciler) kodda, testlerde ve fixture'larda asla gerçek karakter ya da `\u` kaçış dizisi olarak yazılmaz. Kodda `String.fromCodePoint(0x202e)`, fixture'larda `{U+202E}` / `{U+FE01*40}` gösterimi kullanılır. Sebep: araç çağrıları JSON olarak gidiyor ve JSON `\uXXXX` dizilerini gerçek karaktere çeviriyor; bu, eski kod tabanına iki kez görünmez karakter soktu. `tests/security.test.ts` bunu denetler.

## Maliyet kısıtı
Her şey ücretsiz olmalı; yalnızca domain (ve ileride gerekirse VPS) ücretli olabilir.
Şu anki ücretsiz bileşenler: Vercel Hobby planı (ticari olmayan kullanım), GitHub API (kişisel token, yalnızca public okuma), Neon Postgres ücretsiz planı (Vercel'in Storage sekmesinden eklenir, 0,5 GB), OSV API (osv.dev, anahtarsız; kullanıcı 9 Ekim 2026'da onayladı), VirusTotal public API (ücretsiz hesap anahtarı, dakikada 4 / günde 500 sorgu, yalnızca ticari olmayan kullanım; kullanıcı 9 Ekim 2026'da onayladı), npm paketleri (animasyon için Motion, MIT lisanslı), Google Analytics 4 (ücretsiz; kullanıcı 12 Ekim'de istedi, yalnızca ziyaretçi izniyle yüklenir).
Ücretli bir API, SaaS veya kütüphane ekleme. Yeni bir dış servis (KV, VirusTotal API, OSV vb.) eklemeden önce kullanıcıya sor.

## Mimari
Tek Next.js 16 uygulaması (App Router, TypeScript, Tailwind CSS 4, Motion animasyonları), Node.js 22 (`engines: 22.x`). Vercel'e doğrudan deploy edilir; yerelde `npm run dev`.
Next.js 16 eğitim verisindeki sürümden farklı: kod yazmadan önce `node_modules/next/dist/docs/` içindeki ilgili belgeyi oku (`AGENTS.md`). `params` bir Promise'tir; `PageProps`/`LayoutProps` tipleri `next typegen` ile üretilir.

- `src/engine/`: Tarama motoru. Saf TypeScript; yalnızca motor içi dosyaları ve `node:stream`, `node:zlib` modüllerini import edebilir (Next.js, React, `fs` yasak). Web API'si ve CLI aynı motoru kullanır. `tests/architecture.test.ts` bunu zorlar.
  - `types.ts` veri tipleri, `limits.ts` tüm güvenlik limitleri, `errors.ts` hata türleri, `target.ts` girdi doğrulama (`owner/repo`, `github.com/...`, tam URL, `/tree/...` linkleri)
  - `text.ts` güvenilmez metin yardımcıları: satır bölme, uzun satır pencereleri, entropi, `defang`, `sanitize`, `snippet`, `revealHidden`, belge/kaynak kodu/test dosyası tespiti, yorum satırı ve dizge içi tespiti, UTF-16 BOM çözme
  - `github.ts` GitHub API istemcisi (metadata, son commit SHA, sahip hesap yaşı, release digest'leri, tarball akışı)
  - `archive.ts` bellekte, akışla ve limitli tar okuyucu (kendi tar ayrıştırıcımız; pax ve GNU uzun ad başlıkları, checksum kontrolü). `.zip` dosyaları 20 MB'a kadar bütün olarak okunur; arşivdeki her yolu (link ve klasörler dahil) `seen` kümesine yazar.
  - `deps.ts` bağımlılık dosyalarını okur (`package.json`, `package-lock.json`/`npm-shrinkwrap.json`, `yarn.lock`, `pnpm-lock.yaml`, `requirements*.txt`, `pyproject.toml`, `poetry.lock`, `uv.lock`, `Pipfile.lock`); `node_modules/` ve ZIP içindekiler okunmaz. `osv.ts` OSV istemcisi. Kilit dosyaları da ZIP'ler gibi 20 MB'a kadar bütün okunur (büyük projelerde 1 MB'ı aşarlar; yarım bir kilit dosyası ayrıştırılamaz). Daha büyükse `package.json`'daki aralıklara düşülür.
  - `virustotal.ts` VirusTotal istemcisi (v3 `/files/{sha256}`; 404 "unknown" demektir ve asla "temiz" sayılmaz) ve `ReputationService` arayüzü. `archive.ts` programları (PE, ELF, Mach-O; `rules/binary.ts` `executableKind`) `maxExecutableBytes`'a (32 MB) kadar bütün okur, `scanner.ts` SHA-256'larını Web Crypto ile hesaplar.
  - `submodules.ts` kök dizindeki `.gitmodules` dosyasını okur. GitHub'ın arşivi submodule'leri içermez, `git clone --recursive` ise başka repolardan indirir; bunlar taranmaz, raporda `submodules` olarak listelenir. GitHub'daki submodule'ler (`https://`, `git@github.com:`, `ssh://`, göreli `../repo`) doğrulanmış `owner/repo` olarak gelir ve arayüzde yalnızca kendi `/<dil>/scan/<owner>/<repo>` sayfamıza link olur; URL'nin kendisi asla tıklanabilir değildir.
  - `zip.ts` repodaki ZIP'lerin içini bellekte açar (merkezi dizin okunur; yalnızca stored/deflate, şifreli üyeler, symlink'ler ve ZIP64 atlanır). Üye yolu `arşiv.zip!/iç/yol` biçimindedir. Limitler: ZIP başına 2.000 üye, tarama başına toplam 50 MB açılmış veri (zip bombası), ZIP içinde ZIP en fazla 2 seviye. ZIP üyelerinde yalnızca içerik kuralları (`code`, `obfuscation`, `binary`) çalışır (`ARCHIVE_MEMBER_CATEGORIES`): arşivin içindeki bir README ziyaretçiye gösterilmez, içindeki `package.json` klonlayınca çalışmaz.
  - `rules/` kurallar: `base.ts` (Rule arayüzü, `regexRule`, yol eşleme), kategori başına bir modül (`autorun`, `code`, `obfuscation`, `links`, `binary`, `repo`), `index.ts` kayıt
  - `scoring.ts` puan, `scanner.ts` orkestrasyon, `report.ts` güvenli JSON rapor (arayüzün kullandığı tek biçim)
- `src/lib/scan-service.ts`: API ile motor arasındaki katman: girdi doğrulama, iki seviyeli önbellek (örnek belleği 60 sn, veritabanı 1 saat; bellekteki kayıt veritabanındaki ömrünü asla aşmaz), istemci başına hız sınırı (dakikada 6 yeni tarama, 60 veritabanı sorgusu; IPv6 adresleri /64 olarak gruplanır; istemci IP'si `src/lib/request.ts` `clientIp` ile **`x-real-ip`**'ten alınır — Vercel'in koyduğu, istemcinin sahteleyemeyeceği değer; `x-forwarded-for`'un ilk değeri istemci kontrollü olduğu için yalnızca yerelde yedek, aksi halde biri başlığı döndürerek tüm IP limitlerini atlatırdı), aynı anda en fazla 4 tarama, hata kodu eşleme. Yeni taramalar iki kez sınırlanır: örnek belleğinde (her zaman) ve veritabanı varsa tüm örnekler arasında (`src/lib/rate-store.ts`, `rate_limits` tablosu, sabit pencereli sayaçlar): istemci başına dakikada 6 ve site genelinde saatte 500 yeni tarama (`SCAN_BUDGET_PER_HOUR`; bir tarama ~6 GitHub isteği, token saatte 5.000). Bütçe dolunca yeni taramalar 503 `budget_exhausted` alır, son 1 saatin sonuçları gelmeye devam eder. Sınırı aşan istemci genel bütçeyi tüketmez. Veritabanında IP saklanmaz: istemci anahtarının HMAC'ı (anahtar: veritabanı URL'si) tutulur, 1 günden eski satırlar silinir. Sayaç hatası taramayı engellemez (bellek sınırı yine geçerli). `fresh=1` ("Scan again now") önbellekleri atlar ama son tarama 1 dakikadan yeniyse onu döndürür (aynı repoyu tekrar tekrar taratıp GitHub kotasını tüketmeyi engeller). Süre bütçesi yüzünden yarım kalan taramalar önbelleğe ve veritabanına yazılmaz. Veritabanındaki rapor başka bir motor sürümüyle (`engineVersion`) yapıldıysa önbellekten verilmez, repo yeniden taranır. Bu yüzden kurallar, ağırlıklar, puanlama ya da ek kontroller her değiştiğinde `src/engine/version.ts` içindeki `ENGINE_VERSION` artırılır; yoksa kullanıcı 1 saat boyunca eski sonucu görür. Veritabanı hatası taramayı asla bozmaz, yalnızca loglanır.
- `src/lib/virustotal.ts`: Sitenin VirusTotal katmanı. Anahtar `VIRUSTOTAL_API_KEY`; yoksa kontrol kapalıdır (`not_configured`), rapor eskisi gibi VirusTotal linkleri verir. Ücretsiz anahtarın kotası tüm site için ortaktır: dakikada 4, günde 500 istek, `rate-store.ts` sayaçlarıyla (`virustotal-minute`, `virustotal-day`; veritabanı yoksa ya da hata verirse bellek). Bir tarama en fazla 4 canlı istek harcar. Her cevap 1 gün saklanır (`virustotal_cache` tablosu; veritabanı yoksa bellek); "skipped" saklanmaz. VirusTotal 429 ya da 401 dönerse o taramada başka istek atılmaz. Anahtar `log.ts`'te gizlenir.
- `src/lib/log.ts`: Sunucu loglarına yazmadan önce bağlantı dizelerini ve GitHub tokenlarını gizler (Neon sürücüsü bazı hatalarda bağlantı dizesini, şifresiyle birlikte mesaja koyuyor). Sunucu tarafında `console.error` yerine `logError` kullan.
- `src/lib/db.ts` + `src/lib/scan-store.ts`: Kalıcı depolama. Her reponun **son** taraması `scans` tablosunda tutulur (anahtar: küçük harfli `owner/repo`; yeniden tarama kaydın üzerine yazar). Saklanan şey yalnızca sanitize edilmiş rapordur, repo dosyaları asla saklanmaz. Tablo ilk kullanımda `CREATE TABLE IF NOT EXISTS` ile oluşur, ayrı bir kurulum adımı yoktur. Bağlantı: `DATABASE_URL` (ya da `POSTGRES_URL`); yoksa `nullScanStore` devreye girer, site depolamasız çalışır ve listeler boş görünür. Üretimde Neon'un HTTP sürücüsü (sorgu başına 5 sn zaman aşımı), testlerde PGlite (WebAssembly ile gerçek Postgres) aynı `Db` arayüzüyle kullanılır. Kurallar: eski bir tarama yenisinin üzerine yazamaz (`WHERE scans.scanned_at <= EXCLUDED.scanned_at`); tablo oluşturma yarışında kaybetmek (23505/42P07) hata sayılmaz; tablo en fazla 5.000 satır tutar, en eski kayıtlar ara sıra silinir. `HIDDEN_REPOS` (`scan-store.ts`) hiç kaydedilmeyen ve listelenmeyen repolardır; şu an yalnızca sitenin kendi reposu `dorukkino/gitray` (private oldu, public iken taranmıştı; kullanıcı isteği, 10 Ekim). Önceden kaydedilmiş satırı her örnek tabloyu ilk kullandığında siler. Bu, site sahibinin kendi listesidir; taranan repoya konan "beni tarama" dosyaları yine asla desteklenmez. Veritabanına giden her metin `sanitize`'dan geçtiği için iyi biçimlidir (yarım emoji Postgres'in JSON'unu bozar; `truncate` bu yüzden vekil çiftleri bölmez).
- **Yanlış sonucu bildirme + özel admin paneli (17 Ekim, kullanıcı isteği).** Tarama raporundaki "Yanlış mı? Bildir" butonu (`ReportFalseFinding`, karar rozetinin yanında) bir form açar; ziyaretçi neden yanlış olduğunu yazar, `POST /api/report` doğrular, hız sınırlar ve **özel** olarak saklar (`src/lib/report-store.ts`, `false_reports` tablosu; serbest metin + repo/karar/puan/motor sürümü + IP'nin HMAC'ı, ham IP değil; en fazla 2.000 satır). Bildirimler herkese açık değildir; yalnızca site sahibi `/dorukadm`'den okur (bu adres gizlidir: nerede link verilmez, `src/proxy.ts` matcher'ında ve `robots.ts`'te hariç, sitemap'te yok, `noindex`). `/dorukadm` kendi kök layout'una sahiptir (`src/app/dorukadm/layout.tsx`, İngilizce, site başlığı yok; Next çoklu kök layout) ve **yalnızca okur** — veri değiştiren işlem yoktur; tek POST'lar kimlik doğrulamadır. İlk giriş **tek seferlik, token korumalı** kurulum (`ADMIN_SETUP_TOKEN`; hesap yokken ve token doğruyken). Admin girişinde ve genel rapor formunda kullanılır. İmza sırrı `ADMIN_SECRET` (`src/lib/secret.ts` `signingSecret()`; yoksa `DATABASE_URL`'e düşer, o da yoksa rapor/admin kapalı). `src/lib/sanitize-text.ts` serbest metni temizler (kontrol/yön/görünmez karakterleri atar — sınıf `String.fromCodePoint` ile kurulur, dosyada gerçek görünmez karakter yok). Tüm SQL parametrelidir (`$1,$2…`), kullanıcı verisi asla sorgu metnine gömülmez. **Giriş sertleştirmesi (38. oturum güvenlik denetimi):** login scrypt'i kullanıcı adından bağımsız her zaman çalıştırır (kullanıcı adı zamanlama sızıntısı yok) ve çok uzun şifreyi hash'lemeden reddeder (`validPassword`); `/api/report` gövdeyi okumadan 16 KB ile sınırlar (`MAX_BODY_BYTES`); `log.ts` `VIRUSTOTAL_API_KEY` yanında `ADMIN_SECRET`'i de gizler.

## Tarama akışı
1. Repo bilgisini al (GitHub API): kanonik ad (yeniden adlandırılmış repolarda yönlendirme yalnızca `api.github.com` içinde ve en fazla 3 kez izlenir), boyut, oluşturulma tarihi, varsayılan dal, son commit SHA, sahip hesap yaşı, son 10 release'in dosyaları ve `digest` değerleri. Token yalnızca `api.github.com`'a gönderilir, `codeload.github.com`'a gönderilmez, hiçbir yerde loglanmaz.
2. Tarball'ı commit SHA'sı ile akış halinde indir ve bellekte limitlerle oku; içindeki ZIP'leri de aç. Süre bütçesi (45 sn) metadata isteklerini de kapsar.
2b. **Arşiv bütünlüğü kontrolü.** GitHub tarball'ı `git archive` ile üretir ve `.gitattributes` içindeki `export-ignore` dosyalarını dışarıda bırakır; `git clone` ise onları getirir. Bu, payload'ı tarayıcılardan saklamanın bir yoludur. Tarama tam bittiyse commit'in dosya listesi Git Trees API ile alınır (1 istek), arşivde olmayan dosyalar `raw.githubusercontent.com`'dan (API kotası harcamaz, token gönderilmez) ayrıca indirilip taranır (en fazla 300 dosya ve 20 MB; önce çalıştırılabilir/kod dosyaları). İndirilemeyen saklı dosya varsa tarama Eksik sayılır (`maxHiddenFiles`). Liste alınamazsa ya da GitHub listeyi kısaltırsa (`truncated`) kontrol "unavailable" olur ama tarama bozulmaz. Saklı dosya bulunursa `GR-REPO-003` (+5) eklenir. Sonuç raporda `archiveCheck` olarak yer alır. Bir tarama artık yaklaşık 6 API isteği kullanır. Metin dosyaları (UTF-8, BOM'lu UTF-16) metin kurallarına, ikili dosyalar (ilk 8 KB'ta NUL) yalnızca başlık baytlarına bakan ikili kurallarına gider.
2d. **VirusTotal kontrolü** (`GR-BIN-003`). Repoya commit'lenmiş programlar (bütün okunabildiyse) ve son 10 release'in dosyaları (GitHub'ın `digest` değeri; `sha256.sum`, `SHA256SUMS`, `checksums.txt` gibi checksum listeleri, imza ve metin dosyaları hariç) parmak iziyle sorulur. Sıra: test dışındaki programlar, release'lerdeki program ve arşivler, diğer release dosyaları, testlerdeki programlar; tarama başına en fazla 10 dosya (`maxReputationLookups`); fazlası listelenmez, yalnızca sayısı (`notLookedUp`) raporlanır. 5 ya da daha fazla motor "malicious" diyorsa +70 (tek başına Tehlikeli), 1–4 motor +10 (kurulum dosyalarında ve küçük başlatıcılarda sık görülen yanlış alarm; canlıda `astral-sh/uv` böyle 3 dosya verdi). Release dosyaları limit yüzünden yarım kalan taramalarda da sorulur (süre bitmediyse). Sonuç raporda `reputationCheck` (`not_configured`, `none`, `ok`, `found`, `partial`, `unavailable`) ve dosya listesi olarak yer alır; tarama asla bozulmaz.
2c. **Bağımlılık kontrolü** (`GR-DEP-001`, +70, tek başına Tehlikeli). Tarama sırasında bağımlılık dosyaları toplanır, sonra OSV'ye toplu sorgu atılır (`/v1/querybatch`, 1000'lik parçalar, en fazla 5.000 sorgu). Yalnızca `MAL-` ile başlayan kayıtlar (OpenSSF malicious-packages) dikkate alınır: GiTRay zararlı yazılım arar, sıradan güvenlik açığı (CVE) aramaz. Kilit dosyasındaki tam sürüm doğrudan sorgulanır. Yalnızca aralıkla bildirilen paket (`^1.2.0`) için kayıt **her sürümü** kapsıyorsa (typosquat) bulgu üretilir; yalnızca bazı sürümleri ele geçirilmiş popüler paketler (chalk/debug saldırısı gibi) kurulacak sürüm bilinmediği için işaretlenmez, yoksa her repo yanlış alarm verir. Bunu ayırt etmek için tarama başına en fazla 20 kayıt detayı çekilir (`/v1/vulns/{id}`, örnek başına önbellekli). OSV'ye ulaşılamazsa kontrol "unavailable" olur, tarama asla bozulmaz. Sonuç raporda `dependencyCheck` olarak yer alır.

   - Linkler ve sosyal mühendislik (`GR-LINK-*`, `GR-SOC-001`): repo dışı exe/arşiv linkleri, dosya paylaşım siteleri, link kısaltıcılar, arşiv şifresi, "antivirüsü kapat" talimatı, zararlı yazılım satan README (`GR-SOC-002`, 80, tek başına Tehlikeli: en az 3 zararlı araç türü, en az biri saldırıya özgü (builder, crypter, FUD, antivirüs atlatma, cracked, gizli miner), bir fiyat/satın alma sözcüğü ve birinci ağızdan satış çağrısı (mağaza linki, `wa.me`, "contact us", "buy/DM ... WhatsApp/Telegram"); güvenlik ürünleri tehditleri sayar ama saldırı aracı satmaz, tehdit raporları satışı anlatır ama çağrı yapmaz)

   - **Temiz** (<30), **Şüpheli** (30–69), **Tehlikeli** (≥70).
   - **Güçlü sinyal şartı** (17 Ekim, kullanıcı kararı; `scoring.ts` `hasDecisiveSignal`): Tehlikeli (≥70) **belirleyici bir sinyal** ister; yoksa karar Şüpheli'de tutulur ve gösterilen puan 69'a indirilir (`weakSignalsCapped`, raporda ayrı kutu). Belirleyici = tek bir bulgu ≥40 (`STRONG_SIGNAL`), ya da iki ayrı bulgu ≥35 (`HIGH_SIGNAL`; örn. install hook'unda `curl|sh` — hem `GR-AUTO` hem `GR-CODE-002` 35), ya da bir tuzak/dağıtım kırmızı bayrağı (`LURE_RULES`: `GR-SOC-002` malware satışı, `GR-LINK-003` dosya-paylaşım, `GR-LINK-004` arşiv şifresi, `GR-BIN-002` şifreli arşiv). Sebep (17 Ekim, kalibrasyon): büyük meşru projeler çok sayıda zayıf/orta sinyal biriktirip (installer adımı, dokümanda indirme linki, vendored bundle) Tehlikeli çıkıyordu (PowerToys, rustup). Bu bulgular puana tam ağırlıkla girer ve raporda "in a test file" olarak işaretlenir. Test bulguları tek başına **kararı hiç yükseltmez** (17 Ekim, resmî plugin reposu geri bildirimi; eskiden yalnızca Tehlikeli'yi Şüpheli'de tutuyordu, artık Şüpheli'yi de engelliyor): karar test dışı dosyalara göre verilir: test dışı puan Tehlikeli değilse **gösterilen puan test dışı toplama indirilir** (`scoring.ts`), böylece gauge ile döküm tutarlı olur; raporda `testFilesCapped` ile açıklanır ve test bulguları "sayılmadı" (üstü çizili) görünür (`report.ts` `ReportRule.testOnly`, `ReportView`). İstisna: test dışında klonlayınca/kurunca/açınca çalışan ve **komutu gerçekten bir test yolunu çalıştıran** bir `autorun` bulgusu varsa (örn. `postinstall: node tests/setup.js`; `text.referencesTestPath` bulgunun snippet'ine bakar) sınır uygulanmaz, test klasörüne saklanan payload'ı başlatabilir. Komutu testlere değinmeyen bir autorun (`patch-package`, `tsc`) istisnaya girmez (17 Ekim, axios yanlış alarmı: `docs/package.json`'daki `postinstall: patch-package`, `tests/`'teki bir güvenlik testinin `vm.runInContext`'ini Tehlikeli yapıyordu). `GR-AUTO-008` (yapay zekâ hook'ları ve MCP sunucuları) bu istisnaya hiç girmez: kullanıcı asistanı kendi yapılandırır, klonlayınca çalışmaz.
   - **Eksik**: Bir limit taramayı durdurdu ve okunabilen kısım temiz çıktı. İndirmeden önce yakalanan limitler (repo boyutu, Content-Length, süre) de buna dahildir; repo bilgisi ve `partial` bloğu raporda yer alır. `maxRepoSizeKb` 1,5 GB'dır (eskiden 500 MB; 17 Ekim, WordPress yanlış alarmı: GitHub'ın bildirdiği `size` **tüm geçmişi** içerir — WordPress 707 MB geçmiş ama 160 MB çalışma ağacı — biz yalnızca tek commit'in arşivini indiririz, bu yüzden geçmiş boyutuna göre reddetmek yanlıştı; indirmenin kendisi zaten `maxDownloadBytes`/`maxTotalBytes` ile sınırlı). Çok büyük repolar artık reddedilmek yerine okunabildiği kadar taranır. Limit aşımı hiçbir zaman hata olarak bitmez. Eksik yalnızca Temiz'in yerine geçer; okunan kısım Şüpheli ya da Tehlikeli ise o karar kalır ve rapor "kısmi tarama" olarak işaretlenir. Kısmi tarama asla Temiz sayılmaz, çünkü saldırgan payload'ı büyük dosyaların arkasına saklayabilir.

## Kural yazma kuralları
- Kimlik biçimi `GR-<KATEGORİ>-NNN`; ağırlık 1–100; `why` sade bir dille "neden tehlikeli" açıklaması.
- Belgelerde düşük ağırlık (`docWeight`) yalnızca `GR-CODE-*` kurallarında kullanılır. Belge dosyası yalnızca türüne göre belirlenir (`*.md`, `*.rst`, `*.adoc`, README/LICENSE/CHANGELOG gibi bilinen `.txt` adları); klasör (`docs/`) etkisizdir.
- **Arama kalıbı ve yorum bağlamı** (12. oturum, kullanıcı onayı): `GR-CODE-*` bulgusu kaynak kodunda bir arama kalıbının içindeyse (JS/TS regex literali; `RegExp(...)`, `String.raw`, Python `re.compile(...)`/`re.search(...)`, Go `regexp.MustCompile(...)`, Rust `Regex::new(...)`, Java `Pattern.compile(...)` gibi regex kurucularına verilen metin) ya da tam satır yorumdaysa `docWeight` ile sınırlanır (`docWeight` 0 ise bulgu düşer) ve raporda `patternContext` olarak işaretlenir (`text.inSearchPattern`, `rules/base.ts`). Sebep: güvenlik araçları saldırıları böyle tarif eder; GiTRay kendi kural dosyaları yüzünden Tehlikeli çıkıyordu. Aynı satırda metni çalıştıran bir şey varsa (`eval(`, `exec(`, `Function(`, `spawn`, `.source`, `.pattern`, `child_process`, `subprocess`) indirim uygulanmaz; bir regex'in metnini çalıştırmak (`eval(P.source)`, `exec(p.pattern)`) ayrıca `GR-CODE-001` ile tam puan alır. Repoya konan "beni tarama" listeleri (`.gitrayignore` gibi) asla desteklenmez: saldırgan zararlı dosyasını böyle gizlerdi.
- Satır numaraları yalnızca `\n` ve `\r\n` ile sayılır (`text.splitLines`); `\v`, `\f` ya da satır ayırıcı (U+2028) gibi başka ayırıcılar kullanılmaz (`String.prototype.split` ile yalnızca `"\n"`).
- Regex'ler `g`/`y` bayrağı olmadan yazılır (`regexRule` bunu kontrol eder); iç içe niceleyici kullanma (ReDoS), aralıkları sınırla (`.{0,200}?`). Uzun satırlar 10.000 karakterlik örtüşen pencerelerle taranır.
- URL'nin GitHub'da barınması hiçbir kuralda güven sinyali değildir. Yalnızca taranan reponun kendi `releases/download/` ve `releases/latest/download/` linkleri ve varsayılan dala ya da taranan SHA'ya işaret eden kendi `archive/` linkleri muaftır; yol kaçışı içeren (`..`, `%2e`, `%2f`, `%5c`, `\`) linkler muaf değildir.
- Her yeni kural için en az bir pozitif ve bir negatif fixture yaz; `tests/rules.test.ts` kayıtlı her kural için ikisini de ister.
- **Yanlış alarm kalibrasyonu** (7. oturum, 38 popüler repo; sonuçlar `PROGRESS.md`'de). Kural değiştirince `npm run calibrate -- <klon-klasörü>` ile tekrar ölç; `tests/calibration.test.ts` hem zararlı biçimlerin yakalandığını hem de meşru kalıpların sessiz kaldığını kilitler. Bu turdan çıkan ilkeler:
  - Bir şeyi otomatik çalıştıran ama riskli içerik göstermeyen giriş noktaları düşük puan alır (`package.json` scripti, build olayı, dev container: 10; yapay zekâ hook'u: 15). Çalıştırılan dosya zaten kendi kurallarıyla taranır. İndirme, çözme, gizli pencere ya da LOLBin içeren komutlar 35–40 alır. ## Komutlar
- Kurulum: `npm install`
- Geliştirme sunucusu: `npm run dev` → http://localhost:3000
- Testler: `npm test` (kapsam: `npm run coverage`)
- Lint / tip kontrolü: `npm run lint`, `npm run typecheck`; hepsi birden: `npm run check`
- Production build: `npm run build` ve `npm start`
- CLI tarama: `npm run scan -- github.com/owner/repo` (`--json` ile JSON)
- Yanlış alarm kalibrasyonu: repoları `git clone --depth 1 https://github.com/<owner>/<repo> <klasör>/<owner>/<repo>` (küçük harf) ile indir, sonra `npm run calibrate -- <klasör>` (liste: `scripts/calibration-repos.txt`). Dosyalar yalnızca okunur.
- Ortam değişkenleri (`.env.example`): `GITHUB_TOKEN` (fine-grained, yalnızca "Public repositories" okuma, ek izin yok; tokensız saatte 60 GitHub isteği, tokenla 5.000; yeni bir tarama 5 istek kullanır, veritabanından gelen tarama 0) ve `DATABASE_URL` (Neon; Vercel'de Storage sekmesinden bağlanınca otomatik eklenir) ve `VIRUSTOTAL_API_KEY` (isteğe bağlı; virustotal.com ücretsiz hesap → profil → API key). `SITE_URL` (isteğe bağlı; boşsa Vercel'de https://www.gitray.com.tr kullanılır, yalnızca başka bir adres göstermek için gerekir). `ADMIN_SECRET` (admin oturumunu ve captcha token'larını imzalar; `/dorukadm` paneli ve rapor formu için gerekir, yoksa ikisi de kapalı; uzun rastgele değer) ve `ADMIN_SETUP_TOKEN` (ilk admin hesabını kurarken bir kez istenen gizli anahtar). Yerelde `.env.local` dosyasına yazılır, asla commit edilmez.

## Bu bulut ortamına özel notlar (Claude Code on the web)
- Node'un `fetch`'i proxy ortam değişkenini kendiliğinden okumaz: ağa çıkan komutları `NODE_USE_ENV_PROXY=1` ile çalıştır (örn. `NODE_USE_ENV_PROXY=1 npm run build`, `GITHUB_TOKEN= NODE_USE_ENV_PROXY=1 npm run scan -- Dorukkino/GitRay`).
- Konteynerdeki `GITHUB_TOKEN` proxy'ye özeldir; kendi isteklerimize eklenince 401 döner. Bu ortamda `GITHUB_TOKEN=` (boş) ile çalıştır.
- Proxy GitHub API'sinde yalnızca oturuma bağlı repoya (Dorukkino/GitRay) izin verir; `/users/...` ve başka repolar 403 döner. Başka repoların gerçek taraması yerelde ya da Vercel'de denenmeli. Public repolar `git clone` ile okunabilir (kodu çalıştırmadan, yalnızca dosya okuyarak tarandı).
- `api.osv.dev` ve `www.virustotal.com` bu ortamın ağ politikasında kapalı; OSV ve VirusTotal kontrolleri burada test edilemez (testler sahte sunucu kullanır). Gerçek doğrulama Vercel'de yapılır (ya da ortam ayarlarında Allowed domains'e eklenir).
